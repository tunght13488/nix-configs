## Context

This repo installs the OpenSpec CLI via `unstable.openspec` in `home-manager/home.nix`, consuming the `nixpkgs-unstable` input. The current nixpkgs-unstable commit provides OpenSpec 1.4.1. Version 1.5.0 was released 2026-06-28 but hasn't been packaged in nixpkgs yet.

The nixpkgs derivation for openspec uses `stdenv.mkDerivation` with custom `buildPhase` (`pnpm run build`) and `installPhase` (copies `bin/`, `dist/`, `schemas/`, `node_modules/` to `$out`). It accepts `src` and `pnpmDeps` as overridable attributes.

Agent files (Pi skills/prompts and OpenCode skills/commands) are checked into `pkgs/openspec-agent-files/` and linked to home directories by `home-manager/openspec.nix`. These were generated by `openspec init --tools pi,opencode --force` from version 1.4.1.

## Goals / Non-Goals

**Goals:**
- Override the openspec package to build from v1.5.0 source
- Regenerate agent files to match v1.5.0 output
- Keep the build as close to the nixpkgs derivation as possible (minimal overrides)

**Non-Goals:**
- Updating nixpkgs-unstable itself (the override works without a flake update)
- Adopting stores features in this repo's config
- Changing the OpenSpec schema or workflow

## Decisions

### Decision 1: Override in overlays, not as a new package

`overlays/default.nix` already has an `unstable-packages` overlay. We add an `openspec` override there, modifying `src` and `pnpmDeps` on the existing `unstable.openspec` derivation.

**Alternatives considered:**
- *New package in `pkgs/`*: More isolation but duplicates the build logic. The nixpkgs derivation already works — an `overrideAttrs` is simpler.
- *Separate flake input for OpenSpec's own flake*: Would avoid nixpkgs entirely, but adds a flake input and diverges from how other `unstable.*` packages work in this config.

### Decision 2: Compute pnpmDeps hash via fakeHash + build error

The upstream flake uses `pnpm_9` with `fetcherVersion = 3` and hash `sha256-cFY6phUPK4IOthG/aOtMenyQlLYCCilcOIG+G+v/q04=`. But nixpkgs may use a different pnpm version or fetcher format. Rather than guessing, override `pnpmDeps` with `lib.fakeHash`, attempt a build, and extract the correct hash from the error message.

### Decision 3: Regenerate agent files after CLI update

Once the new CLI is installed via `make home`, run `openspec init --tools pi,opencode --force` in a temp directory, then copy the generated files over the checked-in copies in `pkgs/openspec-agent-files/`. The `openspec-agent-files.nix` derivation references these files via `./openspec-agent-files/`, so updating the checked-in copies is all that's needed. No changes to the derivation or `home-manager/openspec.nix` are required.

## Risks / Trade-offs

- **pnpmDeps hash mismatch**: If nixpkgs updates nodejs/pnpm before we compute the hash, the computed hash becomes stale. → Mitigation: the package builds from a specific src + lockfile; the hash is deterministic for those inputs. A nixpkgs nodejs bump won't change it unless the fetcher version changes.
- **nodejs version incompatibility**: Upstream pins `nodejs_20` but nixpkgs uses `nodejs` (currently 24). If 1.5.0's build.js requires node 20 APIs, the build fails. → Mitigation: if this happens, override `nativeBuildInputs` to swap `nodejs` for `nodejs_20`. Fallback cost is one extra build attempt.
- **Agent file content changes**: The v1.5.0 adapter code has CR-escape fixes and possibly other changes. The regenerated skills/prompts/commands may differ subtly. → Mitigation: `git diff` after regeneration to review changes before committing.
