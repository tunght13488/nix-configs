# Design

## Context

See `proposal.md` for the motivation. The existing `pi-box` base image writes `/root/.gitconfig` with an in-container `gh auth git-credential` helper for `https://github.com`; the wrapper provides the existing PAT file to Pi's child processes. SSH credentials and the 1Password socket remain outside the container. The `ka_alpha` workspace mounts its project root read-write (including `repos/`) and its external worktree git common directory through the existing pi-box detection. Its Linux `scripts/sync-repos.sh` uses seven `git@github.com:` origins and runs `git fetch`, branch checkout, and `git reset --hard origin/<branch>`.

## Goals / Non-Goals

**Goals:**
- Make the existing GitHub SCP-style remotes usable in the sandbox with the existing HTTPS helper and token.
- Preserve origin URL values in each checkout; apply the transport change only at Git's URL resolution layer.
- Prove the behavior using the `ka_alpha` project image and its seven configured repositories.

**Non-Goals:**
- Mounting SSH identities, an SSH agent, or the 1Password socket.
- Editing each checkout's `.git/config`, changing remote URLs, or modifying either sync script.
- Rewriting non-GitHub hosts, `ssh://` URLs, or other URL forms in this change.
- Changing the existing GitHub PAT, its permissions, or its mounting behavior.
- Changing the Windows PowerShell workflow.

## Decisions

### Rewrite at shared base-image Git config scope

Add an `insteadOf` rule to the existing `/root/.gitconfig` generated by `home-manager/pi-sandbox.Dockerfile`:

```ini
[url "https://github.com/"]
    insteadOf = git@github.com:
```

Git rewrites matching URL prefixes when opening the remote transport; this does not edit the configured `origin`. The destination host is exactly `github.com`, so the existing HTTPS-scoped `gh auth git-credential` helper supplies the token. Putting the rule in the common base image makes it available to every project sandbox and keeps it in the same image layer as the existing Git overrides.

Alternatives considered:
- Rewrite every clone's remote to HTTPS: rejected because it mutates each checkout, would need repeating in all seven repos/worktrees, and diverges from the workspace's source configuration.
- Add a project-only environment or manifest grant: rejected because the current manifest has no Git URL-configuration contract and every GitHub SSH-form remote in any sandbox has the same transport issue.
- Mount the SSH/1Password agent or add per-repo deploy keys: rejected because the existing PAT already works for HTTPS, while the socket would expose all host SSH identities and deploy keys add unnecessary credential management.
- Run `sync-repos.sh` on the host before starting pi-box: rejected as the primary solution because it would make repository freshness a one-time launch snapshot and would not let the agent fetch on demand.

### Keep the ka_alpha pilot focused

Create its ignored `Dockerfile.pi` from `pi-box init`, extend `pi-sandbox`, and install `@sysid/mmdlint` as the ka_alpha instructions require for Mermaid validation. The Git rewrite remains in the shared base; mmdlint is project-specific. Do not change `sync-repos.sh`, remote URLs, or files under `repos/` as part of implementation.

### Validate sync without discarding local work

First verify all seven GitHub SCP-style URLs with read-only `git ls-remote` from inside the sandbox. Before running the full sync script, inspect `git status --porcelain` for each linked checkout because the script executes `git reset --hard origin/<branch>` and can discard local modifications. If any checkout is dirty, stop before the script and ask the user; do not stash, clean, or reset user work. If all are clean, run the script and verify each checkout is on its configured default branch and at its fetched `origin/<branch>` commit.

## Risks / Trade-offs

- [The broad base-image rewrite changes transport for every `git@github.com:` URL in every pi-box sandbox] → Accepted: GitHub operations already rely on the mounted PAT and HTTPS helper; the sandbox has no SSH path. Keep the rule limited to the literal `git@github.com:` prefix.
- [GitHub remotes outside the PAT's repository access still fail after rewriting instead of attempting SSH] → Expected and safer: the host SSH identity is intentionally unavailable, and failures should identify missing PAT access rather than silently depend on a forbidden credential.
- [`sync-repos.sh` hard-resets each default branch] → Preflight all seven repositories for a clean worktree and stop for user direction if any is dirty.
- [The project Dockerfile's npm package installation can fail if the upstream package or registry is unavailable] → Keep it a separate project layer; the base sandbox remains usable for other projects.

## Migration Plan

1. Add the GitHub `insteadOf` rule to the base image's `/root/.gitconfig`; rebuild the base image by running `pi-box` (the wrapper builds it on each run with layer caching).
2. Run `pi-box init` in `/home/tung/code/knowledge-assistant/ka_alpha`, then add the project-only mmdlint install to `Dockerfile.pi`.
3. Build and launch pi-box in `ka_alpha`; verify the seven `git@github.com:` URLs with `git ls-remote` and verify mmdlint is available.
4. Check all linked repositories are clean. Only then run `./scripts/sync-repos.sh` inside the sandbox and verify default branches match their remote tracking refs.
5. Rollback by removing the URL rewrite and rebuilding the base image; remove the local ignored `ka_alpha/Dockerfile.pi` if desired. No remote URL migration or repo checkout cleanup is required.
